# Neighborhood Rotations

Weekly cafe rotation planning, Smartsheet-aligned records, history, and executive review.

Current implementation: `NeighborhoodRotations.jsx`.

Nessie Global plate-cost pilot handoff: only North/Nessie, the Global planner, and the week beginning `2026-08-17` replace the station's `Selected Mix Food Cost %` card with per-entree plate-cost cards. Standard plates enumerate one selected base plus every valid two-distinct-non-base-side combination and all selected sub recipes. `AMZ: Piccola Italia`, `AMZ: Lemongrass + Lime`, and `AMZ: Chiang Mai` instead enumerate entree plus one selected side and all selected sub recipes. Extensions are excluded, and both percentage endpoints divide by the entree retail price only. Bases are inferred first from explicit `Starch/Grain` source categories (including Smokehouse `Mac & Cheese` / pasta), with a rice/noodle item-name fallback; salad-category rows must remain sides. Keep that rule visible to planners and keep the dollar/percentage results explicitly labeled. Missing composition, component cost, entree cost, or entree retail must suppress the percentage and show an explicit issue. Do not extend this pilot into other cafes, weeks, recaps, Results, summaries, exports, or persistence without a new approved rollout.

Next clean split: move Smartsheet record shaping, rotation calculations, planner sections, and executive results into local modules.

Planner Remote Control handoff: the shared control is intentionally collapsed by default into a full-width black icon bar. Keep all seven actions reachable without horizontal scrolling while collapsed, including at phone widths; preserve real keyboard-operable buttons, accessible names/tooltips, focus rings, and the colored status indicator. Put labels, cafe/week context, copied/update state, and submit guidance behind Expand. Expanded labels must shrink and wrap inside their own button boundaries at desktop and phone widths; phone buttons stack the small icon above the label while desktop buttons keep the inline layout. Do not restore a fixed label width that clips `Generate Menu`, `View/Print`, or `Save Draft`. A live submission must force the details open so the storage warning stays visible. This component is shared across all districts, cafes, and selectable weeks; do not fork its presentation by district.

Planner selector handoff: `ChoiceCard` is shared by District and Café. Preserve its responsive padding/type sizing, `min-w-0`/hidden-overflow button boundary, non-shrinking status dot, and the label's explicit `flex-1 min-w-0 whitespace-normal` safe wrapping so long names such as North `Commissary` stay inside the button at both the approximately 240px narrow viewport and constrained 1024px four-column layout. The browser suite verifies label geometry, horizontal scroll containment, and computed wrapping directly; do not replace these rules with truncation that hides the café name.

Dawson Carvery promotion handoff: use the isolated `carveryPromotionOverride` state and `carveryPromotion` saved-record family. The option is available in every selectable week, supports individual weekdays, and replaces the normal Carvery selections whenever enabled. Do not reuse the rotation-wide Global `promotionOverride` for this path or Dawson's Global station will be affected.

Dawson Moby Pop-Up handoff: `cafeStationsForWeek()` adds the required `mobyPopUp` station only for Dawson weeks starting `2026-08-31` or later. Service is Tuesday through Thursday. Normal state lives in `mobyPopUp`, offers all Global menus plus `AMZ: Carvery`, and exposes fixed capacities of 2 entrees, 3 sides, 2 sub recipes, and 1 extension populated from the selected menu's MenuWorks rows. Promotion state lives separately in `mobyPopUpPromotionOverride`, saves under `mobyPopUpPromotion`, permits only Tuesday/Wednesday/Thursday day toggles (including one day), and replaces/hides the whole normal Moby configuration while enabled. Keep both saved-record families isolated from Dawson Global, Carvery, and the rotation-wide promotion override; Supabase remains authoritative through the existing flexible rotation-record contract, so this feature requires no schema migration.

Moby cafe projection handoff: presentation rows for North/Moby look up the same week's authoritative Dawson rotation. If Dawson is `Submitted` and has a valid Moby Pop-Up menu or promo selection, `projectDawsonMobyGlobal()` attaches a read-time `__dawsonMobyGlobalOverride` that replaces only Moby's visible Global content across leadership/executive cards, the open Draft planner, Results analytics/details, recaps, costs, and print exports. In an open Moby draft, render `DawsonMobyGlobalProjectionSection` instead of the native editable Global section so the projected menu/items are visible with their source, schedule, metadata, and analytics; keep Moby's non-Global stations editable. Never persist this projection into Moby's rotation. Moby's own Draft/Submitted state, completion progress, and native Global choice remain stored unchanged as fallback. Duplicate-menu reporting must continue through `rotationMenuLabelForDuplicateReporting()` so it compares Moby's native Global menu, not Dawson's projected menu. A Dawson Moby promo follows the same rule and affects only Moby Global.
